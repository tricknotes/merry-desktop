# フェーズ0 UI技術スパイク

UI技術を1つに決めるための試作。Tauri、Electron、Go + Wails で同じ最小機能を作り、
ビルド時間・配布物サイズ・常駐メモリを比べる。結果は `docs/phase0-ui-comparison.md` にまとめる。

ここにあるコードは比較のための使い捨て。採用した技術で、フェーズ1に作り直す。

比較の結果、Go + Wails v3 を採用した。ここには Wails のスパイクだけを置いている。
Tauri と Electron のスパイクと計測ワークフローは、コミット `0e51eb8` にある。

## 共通仕様

3つとも次の動きをそろえる。

| 項目 | 仕様 |
| --- | --- |
| トレイメニュー | 起動 / 停止 / 設定を開く / 終了 |
| 状態表示 | 停止中・起動中・稼働中・異常を、トレイアイコンの色とツールチップで区別する。設定ウィンドウにも表示する |
| 設定ウィンドウ | CPU数とメモリ(MiB)の入力欄と保存ボタン。状態ラベルも出す |
| ウィンドウの作り方 | 起動時には作らない。メニューから開いたときに作り、閉じたら破棄する(常駐時の条件をそろえるため) |
| 最後のウィンドウを閉じたとき | アプリは終了せず、トレイに残る |
| VM操作 | `VmBackend` インターフェース越しに呼ぶ。中身はスタブ |

### VmBackend

最低限の5操作。Windows固有の概念(ディストリ名、VHDXなど)は出さない。

| 操作 | 意味 | スタブの動き |
| --- | --- | --- |
| start | VMを起動し、Engineが応答するまで待つ | 1.5秒待って成功。環境変数 `SPIKE_STUB_FAIL_START=1` のときは失敗する |
| stop | VMを停止する | 即座に停止 |
| exec | VM内でコマンドを実行する | 稼働中なら引数を連結して返す。それ以外はエラー |
| status | VMの状態を返す | 内部の状態を返す |
| setResources | CPU数とメモリを設定する | 値を検証して保持する(CPU 1以上、メモリ 1024MiB以上) |

状態の遷移は、バックエンドを呼ぶ側(コア)が持つ。
起動を押すと「起動中」にし、start が成功したら「稼働中」、失敗したら「異常」にする。

### 画面(フロント)

3つとも同じ HTML / CSS / TypeScript を使う(Vite + TypeScript、フレームワークなし)。
違いはネイティブ側を呼ぶ `bridge.ts` だけ。

### ベンチマーク用の目印

差分ビルドの計測で「1行変える」場所を固定するため、次の定数を置いている。
計測スクリプトがこの値を書き換えて再ビルドする。

| 場所 | 定数 |
| --- | --- |
| バックエンド | `BENCH_REVISION`(各スパイクのコア) |
| フロント | `BENCH_REVISION`(`main.ts`) |
