# フェーズ0: UI技術の比較

- 状態: **計測済み。採否の判断待ち**
- 対象: Tauri 2.12 / Electron 45.4.1 / Go + Wails v3.1.0
- 採否は人間が決める。ここでは推奨と理由を示すだけにする。

## 結果

GitHub Actions の `windows-2025` ランナー(4 論理CPU)で、各候補3回ずつ測った中央値。
計測した実行: https://github.com/tricknotes/merry-desktop/actions/runs/45057764399 (コミット `ff2dfc2`)

| 項目 | Tauri | Electron | Wails |
| --- | --- | --- | --- |
| 依存の取得 | 37.6 秒 | 9.0 秒 | 20.1 秒 |
| 初回ビルド | 238.6 秒 | 12.6 秒 | 27.0 秒 |
| 初回合計(依存+ビルド) | 269.5 秒 | 21.6 秒 | 47.2 秒 |
| 差分ビルド(バックエンド) | 51.5 秒 | 8.3 秒 | 1.6 秒 |
| 差分ビルド(フロント) | 51.5 秒 | 8.5 秒 | 1.6 秒 |
| 実行ファイル一式 | 9.0 MB(1ファイル) | 356.9 MB(72ファイル) | 10.1 MB(1ファイル) |
| 同(zip圧縮後) | 2.8 MB | 154.9 MB | 4.2 MB |
| 常駐メモリ Working Set | 13.5 MB | 50.9 MB | 16.4 MB |
| 常駐メモリ Private Bytes | 2.2 MB | 50.2 MB | 47.1 MB |
| 常駐時のプロセス数 | 1 | 3 | 1 |

### 読み取れること

- **ビルド時間は Wails が最も短い。** 差分ビルドはバックエンド・フロントとも2秒以内。
  Tauri は差分でも約50秒かかり、フロントだけ変えても同じだけかかる(画面を実行ファイルに埋め込み直すため)。
- **Tauri の時間はばらつきが大きい。** 初回ビルドは 196〜269 秒、差分は 38〜55 秒と、ランナーの CPU によって変わった。
  ほかの2つは、ばらつきが5秒以内だった。
- **配布物は Electron だけが桁違いに大きい。** Chromium を同梱するため、zip でも約155MB。Tauri と Wails は数MB。
- **常駐メモリは3つとも、仮の目標(200MB以下)に収まっている。** ただし、設定ウィンドウを開いていない状態の値。
  Tauri と Wails はウィンドウを開くまで WebView2 のプロセスを起動しないため、そのぶんが入っていない。
  Electron はウィンドウがなくても、本体・GPU・ユーティリティの3プロセスが動く。
- Wails の Private Bytes が Working Set より大きいのは、Go のランタイムが確保したまま触っていないメモリを含むためとみられる(未確認)。

## 推奨

**Go + Wails v3 を推奨する。**

理由:

1. **開発中の待ち時間が最も短い。** 差分ビルドが約1.6秒で、Tauri(約50秒)とは30倍ほど違う。
   フェーズ0でビルド時間を比べることにしたのは、この差を見るためだった。
2. **配布物とメモリが小さい。** 実行ファイル1つで約10MB(zip で約4MB)。社内配布や自動更新(F-13)の負担が小さい。
   常駐メモリも Electron の3分の1程度(Working Set)。
3. **Docker 周辺のライブラリを Go のまま使える。** Docker Engine の API クライアントや Compose は Go で書かれている。
   F-20〜F-23(Compose 画面、統合ログ、ポート検査、ディスク管理)を、`docker` CLI の出力を解析せずに作りやすい。

懸念と対策:

- **Wails v3 は正式版になったばかり。** v3.0.0 が 2026-10-26、v3.1.0 が 2026-11-01 で、v2 からの大きな作り直しでもある。
  トレイなどの API が変わったり、不具合が出たりするおそれがある。
  対策: バージョンを固定し、`VmBackend` と同じように UI 層も薄く保つ。困ったときは Tauri に移る道を残す(画面は Vite + TypeScript のまま流用できる)。
- **トレイやウィンドウの動作は確認できていない**(下記「未検証のこと」)。フェーズ1の最初に実機で確かめる。

### 他の候補を選ぶ場合

- **Tauri**: 配布物とメモリは最小で、v2 系は2024年から安定している。成熟度を最優先するなら Tauri。
  ただし差分ビルドが約50秒かかり、コアを Rust で書くことになる。
- **Electron**: ビルドは速く、エコシステムも最も成熟している。
  しかし配布物が約155MB(zip)あり、社内配布と自動更新の負担が大きい。推奨しない。

## 計測方法

### 分担

| 項目 | 場所 | 理由 |
| --- | --- | --- |
| 初回ビルド・差分ビルド・配布物サイズ | CI(GitHub Actions `windows-2025`) | 毎回キャッシュのない状態から始められる。3候補を同じ種類のランナーで測れる |
| 常駐メモリ | CI(同上) | 実機では測らない(下記「常駐メモリの扱い」) |

CLAUDE.md の「同一マシンで各3回」は、「同じ種類のランナーで各3回」と読み替えている。
共有ランナーのため回ごとにばらつきがあり、手元のPCでの待ち時間とも一致しない。比較の目安として扱う。

### 手順(CI)

`.github/workflows/phase0-ui-bench.yml` が、3候補 × 3回のジョブを並行して動かす。
各ジョブは `scripts/phase0/bench.ps1` で次を順に行う。

1. 依存のキャッシュ(npm、Cargo の registry、Go のモジュールとビルドキャッシュ、Electron のダウンロード)とビルド結果を消す。
2. 依存を取得する(時間を「依存の取得」として別に記録する)。
3. リリースビルドする(「初回ビルド」)。
4. 実行ファイル一式のサイズと、zip 圧縮後のサイズを測る。
5. バックエンドの `BENCH_REVISION` を書き換えて、もう一度リリースビルドする(「差分ビルド(バックエンド)」)。
6. フロントの `BENCH_REVISION` を書き換えて、もう一度リリースビルドする(「差分ビルド(フロント)」)。
7. ビルドしたアプリを起動し、5分待ってからメモリを測る。

`summary` ジョブが、`scripts/phase0/summarize.mjs` で中央値の表を作る。

### 各候補のビルド内容

| 候補 | リリースビルドのコマンド | 配布物として測るもの |
| --- | --- | --- |
| Tauri | `tauri build --no-bundle`(フロントのビルドを含む) | `spike-tauri.exe` |
| Electron | `vite build` → `tsc` → `electron-builder --win --dir` | `win-unpacked/` 一式 |
| Wails | `vite build` → `go build -tags production -ldflags "-w -s -H windowsgui"` | `SpikeWails.exe` |

インストーラーは作らず、実行ファイル一式で比べる。
Tauri と Wails は Windows 標準の WebView2 Runtime を使うため、その分は含まない。

ビルド設定は各フレームワークの既定に合わせた。Tauri の Cargo の `profile.release` は既定のまま(LTO なし)。
Wails はテンプレートと同じく `-w -s` でシンボルを削っている。
Wails は Windows 用のリソース(`.syso`、アイコンとマニフェスト)を埋め込んでいない。数KB程度の差になる見込み。

### 差分ビルド(フロント)の扱い

開発サーバーで画面に反映されるまでの時間ではなく、リリースビルドのやり直しにかかる時間を測る。
3候補とも Vite のホットリロードを使えるため、開発中の反映時間には差が出にくいと見ている(未計測)。
リリースビルドでは、Tauri と Wails はフロントを実行ファイルに埋め込むため、バックエンドの再リンクを伴う。

### 常駐メモリの扱い

CI のランナーで測った値だけで判断する(2026-11-23 決定)。

- 作業用の Windows 11 Home では Smart App Control がオンで、署名のない exe の起動がブロックされる
  (Electron 版で確認)。Home のため Windows Sandbox も使えない。
- ランナーは配布先のPCと同じではないため、絶対値ではなく3候補の相対的な差として読む。
- 起動から5分待ち、アプリと子プロセス(WebView2、Electron のヘルパーなど)の合計を、
  Working Set と Private Bytes の両方で記録する。設定ウィンドウは開かない。
- 別のPCで測り直す場合は、CI の成果物 `app-*` と `scripts/phase0/measure-memory.ps1` を使う。
